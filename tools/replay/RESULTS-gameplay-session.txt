This is a concrete scheduler blind spot, not proof that every hitch is caused
by that thread. Allocation-rate reductions need controlled follow-up validation.

Streaming analysis
------------------
SessionScan.java reads JFR incrementally with a256MiB Java heap, writes per-submit
CSV, minute statistics, CPU/GC/memory summaries and selected hitch stacks. It
avoids expanding the whole110MiB trace into a much larger JSON object graph.
SystemGC is included explicitly so synchronous collection callers are not missed
by looking only at stop-the-world GC pauses. AllocationScan provides estimated
allocation attribution, with overlapping inclusive contexts kept separate.
