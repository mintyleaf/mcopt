Cave hitch fixes and paired replay, 2026-10-25
===========================================

Changes
-------
1. LodCaptureFreshness privately avalanches its packed64-bit keys using two odd
   multiplications and invertible xor shifts. Long.hashCode previously reduced
   nearby coordinates to x^z; a25x25 neighborhood near the saved location produced
   only60 distinct spread hashes for625 coordinates. Mixing retains coordinate
   identity while dispersing bins. The concurrent map, token replacement/removal,
   late-completion rules, edit coalescing/quiet period and persistent cache format
   are unchanged. The edit queue itself retains canonical coordinates.
   mcopt.lod.captureHash=false opts out at startup.

2. Nine measured stable names join the existing two loading-only preload workers:
   DoubleBlockCombiner and two nested types, zombie arm/animation helpers,
   Fabric ArmorRenderer and the optional selection/collection helpers recorded
   in the real cave flight. No generated lambda/anonymous names are guessed and
   no static initialization is requested. mcopt.preload.caves=false opts out.

   TextureManager's constructor registers exactly five otherwise-unregistered
   SimpleTextures through registerForNextReload: shadow, bat, spider, zombie and
   slime. The existing manager reload prepares their contents asynchronously and
   applies them on its normal executor, owning all GPU objects and replacement/
   close behavior. The helper owns only resource identifiers, preserves existing
   registrations, adds no worker pool and performs no gameplay prefetch sweep.
   mcopt.preload.caveTextures=false opts out. Both groups respect the existing
   global/firstRender/gameplay parents. Image sizes still follow resource packs.

3. Experimental mcopt.metal.recoverDrawables=true (default OFF): after an actual
   failed bounded acquisition, wait for the existing worker before extracting
   and drawing another world frame. If it remains blocked, omit that frame's
   extraction, drawing and stale-color blit. Minecraft's updates, input, ticks,
   resource task execution, submission and cleanup continue. The bounded wait
   prevents an uncapped busy loop. Readiness checks neither launch workers nor
   consume drawables. Resume normal fresh drawing as soon as the result is ready.
   Surface reconfiguration clears state; menus, loading overlays, non-VSync and
   alternate acquire modes bypass the recovery path. Normal frames retain late
   drawable acquisition. Deferred frames are observable in the replay report.

Offline checks
--------------
Core/replay builds and22 Python runner checks pass. Freshness checks pass both
with mixing enabled and through the legacy opt-out, including pending/older
captures, concurrent light invalidation, unload/world reset, raced edits, signed
coordinate distribution and token retirement. Texture checks cover the fixed
bound, existing-entry ownership, idempotence and all parent/feature opt-outs.

An Objective-C check compiles the actual mcdrawable implementation against a
semaphore-controlled fake layer. It verifies bounded waits, exactly one worker,
ready-result ownership, stale resize rejection and close during blocked work.
The final jar contains the linked recovery function and no diagnostic jars.
Whitespace-only cleanup after the benchmark retained byte-identical compiled
class/native payloads; Mixin JSON changed indentation only.
