=====================================================

Finding
-------
A controlled cave resource exercise reproduced a168ms first breaking-overlay
frame. Actual ClassLoad events identify BlockBreakingRenderState (83ms), the
sheeted-decal helper (19ms), FRAPI item bounds (10ms) and block-destruction progress
(7ms) in that frame. The following62ms frame loads entity-shadow helpers. A later

spans, not an inference from an unrelated sampled renderer. Their durations can
include loading locks/I/O and Mixin transformation; do not call them exclusive CPU
cost or add nested class-load spans.

The existing34 priority names did not contain those helpers. Fork.18 adds a separate
12-name gameplay priority group: the seven mining/item/shadow/flame helpers, the
LOD arena-growth helper and four optional Litematica/MaLiLib HUD helpers observed

no generated hidden/lambda names are shipped. The optional FRAPI/HUD types use the

Class.forName(name,false,loader); no extra workers, static-initialization requests,
texture/model prefetch or GPU work. No LOD distances, workers, lighting, graphics,

mcopt.preload.gameplay=false disables only the new group at startup.
mcopt.preload.firstRender=false disables both priority groups; mcopt.preload=false
continues to disable all class preloading. The original general boot list remains.
The counters include already-loaded classes; resolved is not a count of static
initializers run or a guarantee of a particular FPS improvement.

Method and live validation
--------------------------
Same marker-owned isolated instance, original saved-world fixture and frozen LOD
cache restored per run. Source world/builds are retained in the immutable fixture;
only the disposable copy receives the cave room and effects. Supporting mod files
match the normal pack. VSync60, RD12/simulation8, LOD192/Low,4GiB ZGC,2880x1620
world target using the copied0.75 render scale. The normal pack's LOD radius is256;
this is a targeted resource test, not a full reproduction of its background load.

20s warmup, then two30s resource cycles. Each exercises flame/lava sound, stationary
zombie and skeleton, an item in contained lava, breaking overlay/block destruction,
hurt/crit, smoke/extinguish and cleanup. All four runs completed14 effect steps,
22 successful commands, two destroyed blocks and the original320 wall/80 light
edits, with no focus interruption or position error. They pass workload/setup
validity checks. Particle motion, mob variants and burning-item timing are not
bitwise deterministic; this does not replay actual player combat inputs. Ongoing
wall/light work and retained drops also differ between cold/warm cycles.

The separate passive probe applies all14 target method contracts successfully in
the real pack and records named resource/subsystem events.2ms ClassLoad events,
20ms CPU/native samples and50 allocation samples/s; VM inventories, native sampler
and GPU pass splitting off. GPU/submit telemetry retained. The probe/replay are
excluded from the production release jar.

Remaining gaps and diagnostic correction
----------------------------------------
The seven-helper candidate's first phase-entry outlier includes54ms loading the
replay's own Marker event class, plus optional Litematica HUD helpers. Marker
registration now occurs before recording/warmup. This is a harness correction;
its removal must not be credited to a production gameplay fix. The separate HUD
helper preloads address the actual optional-mod class loads. The same capture
also exposes a38ms render-thread load of LodArenaGrowth; the final list includes
that actual arena-migration helper, without initializing or allocating an arena
in advance.

The final run's only >50ms game-frame interval is80ms near measured+1s. The matching
main-submit interval is68ms and contains64ms in SDL event polling. These are two
interval definitions around the same pause, not additive costs. No overlapping
long VM stop establishes a profiler-inventory explanation here. Its native/OS
cause remains unresolved; no SDL work is dropped or moved off the macOS thread.
The final run has no in-flight pipeline compilation, allocation stall or System.gc
in its analyzed window. GC pauses peak0.260ms; JFRSafepointWrite peaks0.318ms. No
class-loader inventory events/operations remain. Final first-breaking max17.703ms
is close to the16.667ms budget, not a promise that every action stays within it.

Textures were much smaller in these runs: zombie/skeleton, destroy_stage_5 and
shadow registrations took roughly2-6ms in the initial capture. The final retained
sound-play span is2.934ms; earlier measured audio requests/device checks were also
small. There is no evidence here for preloading all mob textures, sound buffers or
particles. Other resource packs, entities and effects are not covered.

Memory/interpretation limits
----------------------------
The user reports a newer heavy-caving session with an almost free machine and
little/no paging. That particular session was not captured; do not label it a
paging problem on the strength of earlier recordings.

These replay manifests contain nonzero system-wide swap-counter deltas. They span
launch/world load through exit, not just the measured60s, and are page-equivalent
counters rather than exact disk traffic. OS cache/swap/JIT/thermal differences
remain confounds. The tests do not establish a zero-paging counterfactual or
identify what process caused a particular pause. Direct class-load names and
scope movement remain stronger evidence than timing percentages.
